# キャスト円卓（円卓＋登場人物・会話ログ付き）

[円卓会議](../roundtable/SKILL.md)の手順（議題を固める・独立に検討させる・統合して返す・決めるのはユーザー）をそのまま使い、次の3点を足したハーネス。

1. **登場人物が必ず座る**（作中人物を円卓の正式メンバーにする）
2. **会話そのものをログに残す**（要約ではなく「話者：台詞」の会話文）
3. **ログから裏会議をいつでも作れる**（変換の約束事を固定）

## 1. 議題と参加者

- 議題・目的・制約・今回決めたいことを親が整理する。事実は自分で調べ、ユーザーに聞くのは判断だけ。
- 物語の正本（`docs/production/narrative.md`、`docs/production/characters.md`、章の企画書、`src/story.ts`、`src/quests/chapterScenes.ts`）と、未公開の裏設定（narrative.md「未公開の裏設定」）を全員に渡す。**裏設定をゲーム内で明かす案は出させない。**
- 円卓（必ず全員）：肯定派・中立派・否定派・ユーザー代弁者・AIの代弁者・先生。役の重点は [円卓会議](../roundtable/SKILL.md#2-参加者を選ぶ) のとおり。
- 登場人物：議題に関係する人物を3〜8人選ぶ（主人公、ハンナ、村長エルド、オル、フミ、グラフィウス、悪レンジャー、敵役、新キャラなど）。1つのサブエージェントにまとめて演じさせてよい。新キャラの名前は「仮」と明示する。未確定の設定（両親の生死、騎士の正体、魔王の動機など）を確定させない。作者「めたっぴ」と「魔王」は楽屋でのみ登場できる（本編の設定は語らせない）。

## 2. 第1幕：独立発言（並列）

- Agent ツールで役ごとに別のサブエージェントを `run_in_background: true` で同時に起動する。互いの意見は見せない。検討だけで、ファイル変更・commit・push はさせない。
- 各自の返却形式（この順）：
  1. `確認した範囲：` 1行
  2. **会話**：自分の役の口調で 6〜12 行。形式は `話者：台詞`（登場人物担当は人物ごとに話者名を変える）。仮想の台詞であることは前提なので、台詞の中に「（仮想）」は書かない。
  3. **要点**：2〜4件（根拠または仮定・影響・具体案・確かめ方）
  4. **楽屋のボヤキ**：1〜2行（性格崩壊OK。裏会議の素材）

## 3. 第2幕：反論（往復）

- 全員の第1幕がそろったら、親が「他の参加者の主張」を3〜6行に要約し、`SendMessage` で各参加者に渡す。
- 依頼：「名指しで1人以上に反応する会話を 3〜6 行（`話者：台詞`）、考えが変わった点があれば1行で」。
- これで、ログが独り言の羅列ではなく、実際に言い合った会話になる。時間がないときは第2幕を省略してよいが、ログにその旨を書く。

## 4. 統合（ユーザーへの返答）

[円卓会議の4.](../roundtable/SKILL.md#4-統合して返す親) の順（一致点🔴🟡🟢・立場ごとの指摘・対立点・作中人物の声・決めてほしいこと最大4問＋おすすめ）で返す。多数決で決めない。実プレイ・ユーザー調査をしていないことを明記する。

## 5. 会話ログを残す（必須）

`docs/production/roundtable-logs/<YYYY-MM-DD>-<短い英語のslug>.md` に、次のひな形で書く。**要約で置き換えず、返ってきた台詞をそのまま並べる**（誤字・言い回しの手直しだけ可）。

```markdown
# キャスト円卓ログ：<議題>（<日付>）

議題：…／目的：…／今回決めたいこと：…
参加者：肯定派・中立派・否定派・ユーザー代弁者・AIの代弁者・先生／登場人物：…
注意：決定ではない。採用はユーザーの回答で決める。台詞はすべて仮想。

## 第1幕 独立発言
### 肯定派
肯定派：……
（要点）- …
### …（全員分）

## 第2幕 反論
肯定派：否定派さん、それは……
否定派：……

## 楽屋のボヤキ
肯定派：……
ケシ：……

## 親のまとめ
（ユーザーに返した一致点・対立点・質問の要旨）

## ユーザーの決定
（ユーザーが答えたら追記する。日付つき）
```

- ユーザーが答えたら「ユーザーの決定」を追記する。企画書など正本の資料には、決定事項だけを反映し、ログへのリンクを張る。
- 書いたら `node scripts/production-inventory.mjs --write` と `--check` を通す。

## 6. 裏会議に落とし込む（いつでも）

ユーザーが「裏話にして」「裏会議に足して」と言ったら、ログから `src/quests/backstageMeetings.ts` に新しい回を足す。

- 回の形：`{id, title:'第N回', theme:'<議題を砕いた一言>', unlocked:save=>…, lines:[…]}`。解放条件は、その議題が扱った章のクリア（例：`save.quests?.['royal-gate-intro']?.step==='complete'`）。
- 話者の対応（既存のヘルパーを使う）：肯定派 `pro`、中立派 `mid`、否定派 `con`、ユーザー代弁者 `user`、AIの代弁者 `ai`、作者 `metappi`、魔王 `demon`、本編の面々 `hero`/`hanna`/`mayor`/`ol`/`fumi`、グラフィウス `graphius`、悪レンジャー `nozomi`/`tsukune`/`nurie`/`keshi`。ヘルパーのない人物（先生・道化師など）は `say('名前','顔')` で足す（顔は既存の face キーか絵文字）。
- 立ち絵のポーズ：`'normal'|'propose'|'down'|'surprised'`。提案は propose、落ち込みは down、ツッコまれたら surprised。
- 中身：ログの台詞を素材に **20〜40行** の楽屋コントにする。語り手の一行目は「実は裏で、こんな会議をしていました。」系で始める。性格崩壊・メタ発言OK（前の回の流れを汲むと良い）。**未公開の裏設定（悪レンジャーが最終決戦で助けに来る）と未確定の設定は絶対に書かない。**作者の立ち絵（文字入りシルエット）は反転させない（既存の no-flip の仕組みに任せる）。
- 足したら `npx tsc --noEmit -p .`、`npm test`、`tests/e2e/backstage-menu.test.mjs` を通し、タイトルの「おまけ：裏会議」から実際に再生して1回確かめる。

## 注意

- このスキルの結果は検討であって、ユーザーの承認ではない。
- 画像が必要な案は `/agent-coordination` に従って Codex へ依頼する前提で書く。
- 既存のログ：`docs/production/roundtable-logs/`（2026-11-22 の2件は要約形式。会話形式はこのスキル以降）。
