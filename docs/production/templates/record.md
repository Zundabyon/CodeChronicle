# 制作・変更履歴のひな形

共通規則の正本ではなく、その時点の事実を保存する。後の共通仕様変更で過去の指示や結果を書き換えない。

| 項目 | 記入する内容 |
|---|---|
| 日付・対象・結果 | 採用/不採用/撤回/未対応、対象と用途 |
| 使った仕様 | 共通仕様と固有設定のパス、参照したcommitまたは日付 |
| 入力 | 実際に渡した参照、役割、最終プロンプト/変更要求 |
| 制作方法 | 使用したツールと実際に指定できた設定。存在しないquality等を記録しない |
| 成果物 | プロジェクト内の保存先、元の出力、版 |
| 実測・登録 | 画像寸法・alpha・crop・anchor等の登録先、コードなら対象差分と版 |
| 確認 | 実行したテスト、実画面、対象環境、結果、未実行の範囲 |
| 採否の理由 | 共通規則に反する点と個人の好みを区別 |
| 次回への反映 | 用途別の再利用規則に反映するか、固有設定だけに残すか |

生成履歴は通常 `docs/art/`、既存の画像隣の履歴も[索引](../records.md)から参照できるようにする。コード・物語・音などは既存の設計記録/履歴の所在を参照し、新しい並立台帳を増やさない。根拠のない過去の生成情報を補完しない。
