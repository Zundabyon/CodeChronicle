# CodeChronicle 素材分類・品質基準

監査日: 2026-10-19。対象は `src/world/catalog.ts`、`TerrainTile.tsx`、`WorldScene.tsx`、`world/WorldChip.tsx`、`style.css` と `public` の画像。既存の精細な家・教会・ベッドの描写を品質基準として維持する。低解像度のキャラクターや簡素な小道具をこの基準へ近づける。既存画像を単純な図形や粗いドットへ置換しない。

参考: [AM0500「AIでFF6風のようにきれいなドット絵マップ素材を簡単に作る方法」](https://note.com/am0500_lab/n/n50606ae6f6db)（2025-07-18）。参考にするのは64×64の論理タイル、精細な陰影、俯瞰のマップ、接続する境界という方向性。記事のプロンプトは完成品質を保証しないため、生成結果を実画面で確認する。本書の左上光源・建築寸法・分類は本プロジェクトの規約。

## 4分類と14ジャンルは別の軸

| 素材分類 / catalog | 役割 | 例・寸法の基準 |
| --- | --- | --- |
| 地形 / `terrain` | 床、道、水面、地形境界。タイル接続と歩行可否を持つ | 草・砂・木床は1マス64×64px。山は地形＋立体overlay |
| 建物 / `building` | 複数マスの建築、門、構造壁。見た目と通行フットプリントを分離する | 家・教会は5×4マス＝320×256論理px。遺跡門は現状3×3 |
| 小道具 / `prop` | 家具、植物、宝箱、装飾。地形を置き換えず重ねる | ベッド、棚、樽、井戸、木。寸法は各visualのマス数 |
| キャラクター / `character` | 主人公、NPC、敵、騎士。歩行や向きを表す | 約1マス。ワールド表示と肖像・立ち絵は別素材でよい |

`terrainSets` は**地形ジャンル14種の登録名**であり、4分類や14個の完成マップを意味しない。`TerrainDefinition.set` にだけ直接格納され、建物・小道具・キャラクターには現状 `set` フィールドがない。以下の後3列は制作時の対応方針であり、実装済みという意味ではない。

| terrainSets / 表示名 | 登録済み地形チップ | 建物の対応例 | 小道具の対応例 | キャラクターの対応 |
| --- | --- | --- | --- | --- |
| `grassland` 草原 | grass, meadow, road | 町の家・教会 | 木・花壇・井戸 | 主人公・町NPC・草原の敵 |
| `river` 川・湖 | river | 水辺の建築候補 | 水辺の植物候補 | 水辺に配置する人物・敵 |
| `sea` 海 | sea（水面画像はriverと共用） | 海岸の建築候補 | 海岸の装飾候補 | 海辺に配置する人物・敵 |
| `cave` 洞窟 | 未登録 | 洞窟入口候補 | 岩・鉱石候補 | 洞窟の人物・敵候補 |
| `mountain` 山 | mountain, fieldBoundary | 山地の建築候補 | 山地の装飾候補 | 山地の人物・敵候補 |
| `desert` 砂漠 | sand | 砂漠の建築候補 | cactus | 砂漠の人物・敵候補 |
| `snow` 雪 | 未登録 | 雪国の建築候補 | 雪や氷の装飾候補 | 雪国の人物・敵候補 |
| `abyss` 奈落 | 未登録 | 奈落の構造物候補 | 奈落の装飾候補 | 奈落の人物・敵候補 |
| `space` 宇宙 | 未登録 | 宇宙の構造物候補 | 宇宙の装飾候補 | 宇宙の人物・敵候補 |
| `otherworld` 別世界 | 未登録 | 別世界の建築候補 | 別世界の装飾候補 | 別世界の人物・敵候補 |

| `underworld` 冥界 | 未登録 | 冥界の建築候補 | 冥界の装飾候補 | 冥界の人物・敵候補 |

この変更は既存4分類の品質統一を対象とする。未登録ジャンルの新規マップ・世界設定・敵・物語は別途設計する。

## 画面と制作の共通基準

- ワールドの**論理1マス＝64px**。CSSの実表示は `--tile-size` に従い32/48/64pxへ縮む。素材寸法とブラウザ表示pxを混同しない。
- 視点は既存建物に合わせた俯瞰で、屋根・上面と正面が見える。新素材だけをアイソメトリックの菱形グリッドや真正面にしない。
- 主光源は左上。上面と左上の稜線を明るく、右下や接地面を暗くする。教会の窓や遺跡門の魔法光は局所的な発光として併存してよい。
- 石積み、瓦、木目、布の折り目に段階的な陰影を残す。原画が大きいだけではピクセル密度が揃ったことにならない。家・教会・ベッドと**同じ表示倍率**で比較し、輪郭線の太さ、1マス内の情報量、素材感、接地影を揃える。
- 画像をCSSで無条件に縦横伸縮しない。64×64の床は正方形。建物は必要な占有マス数に合わせて構図を設計する（5×4なら320×256論理px）。原画は大きいまま保持してよく、名前だけで実寸を判断しない。
- `Visual.width/height` と `anchor` はマス単位。`blockedCells` は配置点からの整数オフセットで、画像の透明余白・庇・樹冠と通行禁止セルは同一ではない。家・教会の19セルは5×4から入口 `(2,3)` を除いた形。
- 肖像・会話立ち絵・プロローグ絵はワールド64px制約の対象外。細部や表情が読める専用解像度でよい。

`TerrainTile.tsx` の `viewBox="0 0 16 16"` と16単位のpatternは**SVG座標系**であり、画像を16×16PNGへ変換しているわけではない。画像の64pxテクスチャは1マスの表示領域へ描かれる。現状の輪郭計算は粗い座標で段差を作るため、岸・道の外形と精細テクスチャの密度差は残る。改善時もテクスチャを単色図形へ置き換えない。

目視で家・教会・門の上面と稜線は左上を中心に明るく、庇の下・右側・接地は暗い。ベッドは小さくても布と木枠が読める。一方、生成画像の局所的な陰影まで完全に単一光源とは断定できない。光源・陰影・ピクセル密度の最終判定はPNGヘッダではできないので、64px基準と実表示の両方でレビューする。現行CSSの右下へのdrop-shadowは共通接地表現。統合側では画像に `object-fit:contain;object-position:center bottom` を追加済みで、門・サボテンの比率を保って枠内へ収める。

## 小道具アトラスの扱い

小道具統合は別担当。統合仕様は `maps/props/props-atlas-v2.png`、**1448×1086px、透過原画、12物体の実測矩形**。これは切り出し元の画像全体で、64px個別タイルの命名・寸法検査を適用しない。

`renderer:'atlas'` の `sourceWidth/sourceHeight` はPNG全体の寸法、`frame:[x,y,width,height]` は余白を除いた画像領域、`Visual.width/height` はワールドの論理配置枠。frameは画像境界内に収め、描画は比率を保って枠へ収める。等間隔セルではなく `src/world/propArt.ts` の実測値を使い、実画像全体の境界で検査する。元PNGは再保存・劣化させない。64pxの論理基準はアトラスの物理ピクセル数を強制縮小する規則ではない。

## 再現できる検査

```sh
node scripts/check-art-assets.mjs
```

Node.js **22.15以降**が必要（標準 `node:module` の型除去・ロードフックを使用）。npm依存追加・ビルド・画像変換は不要。PNGは `fs` でバイナリヘッダを読み、signature/IHDRと実寸を確認する。スクリプトは作業ディレクトリに依存せず、ファイルを書き換えない。

検査するもの:

- public内すべてのPNGヘッダと寸法名。既知の大原画4件は寸法を限定した警告とし、未登録の命名不一致は失敗。
- src内の静的画像参照と、実際のcatalogを評価した地形・画像visual・overlay・atlas参照の存在。
- 地形テクスチャの正方形、terrainSetの存在、visual寸法とanchorの妥当性。
- 通行フットプリントの整数・重複・画像枠との交差。透明余白を許すためセル全体の包含は要求しない。家・教会は5×4・入口を除く19セルを追加検査。
- PNGと配置枠の縦横比（差2%超）、配置枠の原寸超過。contain時は実際の拡大率と一致しない。門・サボテンの比率差、木・山の枠寸法、門の空フットプリントは既知警告。
- atlasの宣言原寸とPNG実寸の一致、frameの正整数寸法と画像境界。

監査時点の結果は **46 PNG、47参照、14 terrainSets、10警告、0エラーでPASS**。別担当のアトラス・人物統合後は件数が増える。WARNは既知差異の可視化で、PASSは機械的な条件を通ったという意味。PNG圧縮データの完全性、動的に組み立てられるcatalog外のパス、SVG内の外部参照、全マップ配置の到達性、光源や美観はこの検査の対象外。ゲーム内通行の検証は既存のworld/map-reachabilityテストで補う。

残る判断は、門の3×3枠と原画比率、サボテンの縦長配置枠、木・山の拡大、岸と道の粗い輪郭、人物・小道具の描写密度。catalog・共通CSS・WorldChipの変更が必要なものは統合担当へ報告し、この監査で占有セルやイベントを変更しない。
