# CodeChronicleのゲーム素材

細かく可愛いSFC時代のRPGの雰囲気を、既存素材と同じ画面で成立させる。FF6を意識した好みは視点・陰影・UIとの調和の参考にし、固有のキャラクターや素材の複製は指示しない。

このSkillはプロジェクト固有の品質判断を扱う。ラスター生成・編集には利用可能な `imagegen` スキルを読み、その実行方法に従う。生成ツールを使わない品質レビューでは画像を新規生成しない。

## 最初に確認するもの

- リポジトリの [素材分類・品質基準](../../../docs/art-direction.md) を読む。論理1マス64pxと、原画寸法・CSS表示pxは別の値。大きなPNGや `image-rendering:pixelated` だけで精細さを保証したと判断しない。
- 対象を実際に表示するコードと参照画像を追う。ワールドは `src/world/catalog.ts` と `src/world/WorldChip.tsx`、人物は `src/WorldCharacter.tsx`、会話は `src/CharacterPortrait.tsx`、敵は `src/EnemySprite.tsx` と遭遇・戦闘側を確認する。特別な分岐やCSS描画も対象。
- 対象と同じ分類の良好な既存画像を `view_image` で確認し、必要なら生成時の参照画像として渡す。ファイル名を書いたり「同じスタイル」と言うだけで参照を渡したことにしない。
- 小物は `public/maps/props/props-atlas-v2.png` と `src/world/propArt.ts`、人物は `public/portraits/faces.png` と既存のワールド人物、敵は `src/world/memoryEnemyArt.ts` を出発点にする。既存の簡易SVGや粗い仮素材は品質の見本にしない。

## 生成仕様と見た目

生成前に、用途・視点・表示サイズ・参照画像・維持する特徴を短く定める。「pixel art」「16-bit」だけでは大きな四角いドットや少数色へ寄り得る。参照に合わせ、細かな画素のまとまり、石目・木目・布・金属の段階的な陰影、輪郭の太さ、左上光源、接地影を具体的に指示する。色数や原画サイズを全素材へ一律に固定しない。

- 小物・建物：既存の俯瞰に合わせる。物体全体を収め、地面の貼り付けや不要な背景・文字を避ける。透過素材はツールの `transparent_background:true` を指定し実alphaを確認する。
- 人物：ワールドの体型と会話の胸像は用途別に作る。同じ人物の兜・髪・服・装備・配色などの特徴を共有し、会話用の大きさへ小さな歩行絵を引き伸ばして済ませない。謎の騎士は顔を兜で隠す特徴を維持する。
- 敵：マップ・遭遇・戦闘のそれぞれで認識できる輪郭と特徴を保つ。個体IDと絵柄の種別を混同せず、既存セーブの討伐IDを変えない。
- 状態差分：開閉扉などは確定した元絵を編集対象にし、外枠・足元・キャンバス位置を維持する。別々に生成して形がずれる場合は揃え直す。
- 歩行や方向が必要な依頼では、フレーム寸法・順序・足元と透明余白も合わせる。静止画だけで歩行対応済みと報告しない。

通常は1素材ずつ生成する。スプライトシートが明示的な成果物なら、各物体の重なり・欠け・実測切り出し範囲を確認する。生成原画のピクセル数を指定どおりと仮定せず、PNGの実寸を測る。組み込みツールに存在しない `quality` や `size` パラメータを作らず、品質調整を理由にCLIへ自動で切り替えない。

## 組み込みと採用判断

1. 最終候補をバージョン付きのパスで `public/` へ保存し、元絵を残す。画像加工は `imagegen` のルールに従う。生成先ディレクトリだけにプロジェクト依存を残さない。
2. 画像の原寸、透明余白、縦横比を確認する。atlasの `sourceWidth/sourceHeight` と `frame` は実測し、余白を除いた枠で比率を保つ。元画像を無理に64pxへ縮小保存しない。
3. `Visual.width/height`・anchor・当たり判定は別々に扱う。見た目だけの依頼でマップ、イベント、通行範囲を変更しない。扉の開閉や人物の歩行で足元が跳ねないか確認する。
4. 同じ表示倍率で既存素材と並べ、輪郭・描き込み・色調・素材感・キャラの大きさを比較する。単体の拡大画像が綺麗でも、この比較で浮けば採用しない。
5. 変更した描画経路を実画面で確認する。人物はマップと会話、敵はマップと遭遇・戦闘、扉は開閉両方。PCとスマホで欠け、背景残り、縮小時の潰れ、読めないシルエットを点検する。表示不良がcropやCSSに由来する場合は生成を繰り返す前に描画側を直す。

実装上、謎の騎士は `src/MysteriousKnight.tsx` にworld/会話の別分岐がある。2026-11-02の確認時、worldは生成PNG、会話は32×40の簡易SVGだった。作業時に現状を再確認し、一方だけの更新で両方を改善済みと扱わない。このSkill追加だけでは騎士画像は変更されない。

## 検証と記録

画像・登録を変更したら `npm run check:art`、関連する表示・通行テスト、`npm run build` を実行する。共通rendererを変えた場合は影響する既存表示も確認する。画像検査のPASSは光源・美観・実画面の品質を保証しない。Skillだけの変更ではアプリテストや有料の画像生成を繰り返さず、Skillの構文と参照先を検証する。

生成時は `docs/art/` に、実際に渡した参照画像と役割、最終プロンプト、使用した生成方法、保存先、原寸とcrop、実画面での確認結果を記録する。参考例は [泉・封印扉の制作記録](../../../docs/art/memory-props-v2.md)。記録のために外部への公開やpushは行わない。

報告では変更した素材と表示箇所、実画面の確認結果、保存先、未対応箇所を短く示す。レビュー依頼だけなら問題点と修正案を示し、画像の差し替えは行わない。
