# 全ジャンルの共通ルール

## 分類と管理元

- 主分類は[制作の入口](index.md)の9ジャンル。対象（人物・建物など）、用途（会話・歩行など）、媒体（画像・音・コードなど）、環境（草原・洞窟など）、状態（開・閉など）は別の軸。すべてを一つのフォルダ階層で表現しない。
- 手順はSkill、制作規約はこの案内と用途別仕様、実行時の事実は型付きコードや実素材、生成時の事実は制作履歴が管理する。同じ情報の正本を二つ作らない。既存の専用規約がある場合はリンクする。
- 共通仕様の変更が既存素材へ自動適用・再生成されたとは扱わない。影響する要素を列挙し、既存採用物を変更するかは依頼範囲で判断する。
- 固有設定で変更できるのは見た目・構図・対応する動きなど用途の許す項目。保存ID・採点の公平さ・確認前のデータ不変などの契約を例外扱いして弱めない。

## 共通化して使う順序

1. 対象・用途・期待する動作を決め、既存の管理元と比較例を確認する。
2. 共通ルール＋用途別仕様＋固有情報を組み合わせる。固有情報と共通規則が衝突したら、理由を示して仕様を調整する。
3. 生成や実装で得た実測値を、実行側の登録先へ反映する。設定を書いただけで機能追加済みとしない。
4. 対象に関係する検証を行う。通った範囲・未実行・不採用・未対応を区別し、履歴へ残す。

## 識別子と状態

種類ID・素材ID・配置個体ID・保存IDを混同しない。同じ敵種を複数置いても討伐記録は個体ごと。キャラクターは複数用途の画像を持てる。素材ファイルの名前変更だけで人物・敵・クエストのIDを変えない。

制作上の日本語カテゴリ名を揃えるために、公開済みの問題ID・エリアID・クエスト/step ID・宝箱IDを改名しない。名称変更が必要なら保存移行まで別の変更として設計する。

## 対応状況の表記

| 表記 | 意味 |
|---|---|
| 規約あり | 制作・確認方法を再利用できる。汎用の実装や素材があるという意味ではない |
| 定義で追加可能 | 現行の型・登録経路の範囲で追加できる。登録・検証は必要 |
| 専用実装あり | 特定対象向けのコードがある。対象を替えるだけでは動かない場合がある |
| 未対応 | 素材または実装がなく、追加の設計・実装が必要 |

## 世界観と品質

失われた知識を冒険の中で学び直し、力と日常を取り戻す。既存の事実・章・人物の特徴は[物語](narrative.md)の管理元で確認する。新たな設定や物語上の結論を、生成プロンプトだけで確定しない。

可愛いSFC時代のRPGという美術基準は[素材分類・品質基準](../art-direction.md)が正本。FF6は好みや表現の参考で、特定作品の固有素材を複製する指示ではない。画像の大きさと描き込み密度を区別し、同じ実表示サイズで比較する。
