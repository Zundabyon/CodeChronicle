# ClaudeとCodexの連携

[基本分担](../../../docs/production/operations.md#エージェントの基本分担)に従う。Claudeが壁打ち・設計・コーディング・受け入れ確認、Codexが画像生成・参照編集・制作記録を担当する。ユーザーは、この分担に必要なOrca担当の起動と内部メッセージの送受信を許可している。同じ作業範囲の依頼・質問・差し戻しを毎回ユーザーの伝言待ちにしない。仕様決定、外部への投稿、commit/push/公開の権限をこれで拡大しない。

## 実行環境を読む

Orcaの `orchestration` Skillがあれば読む。利用できない場合は `ORCA_CLI_COMMAND` が示す実行ファイル（未設定のmacOSでは `orca`）で `skills get orchestration` を実行し、そのバージョンの手順に従う。CLI引数・通知・復旧方法を推測しない。非Orcaのサブエージェントを、別サービスのClaude/Codexとして代用しない。

## Claudeが依頼するとき

1. 依頼と現行ファイルを確認し、既存の完成画像・制作記録で満たせるものは再生成しない。第二章の生成済み17枚は[制作記録](../../../docs/art/chapter-two-assets-v1.md)を入口にする。
2. `game-art` に沿って、対象・用途・確定特徴・参照画像の役割・寸法/透過/向き・保存先・受け入れ条件を依頼書へまとめる。担当が書き込める画像と制作記録のパスを明示し、`src/` はClaude所有とする。他の担当の変更を戻さないことを伝える。Codexには、着手時に組み込み画像生成ツールの有無を確認し、なければ不足として報告するよう指示する。API/CLI課金経路への無断切替はしない。
3. 読み込んだOrca手順の `orchestration worker-start` で `--agent codex` を指定し、自己完結した依頼を送る。長い依頼は `--spec-file` を使う。同じ作業場所は所有ファイルが重ならない場合に使い、競合する場合だけOrcaに別作業場所を作らせる。返却を受けるための依頼なので、一方的なhandoffで終わらせない。
4. 起動受領のTask/Dispatchと次の指示を確認する。送信済み・実行中・返却済み・組み込み済みを区別して報告し、待機はOrcaの通知に委ねてターンを終了する。無限ポーリングや独自のwatchを作らない。

## 質問と成果物の往復

- Codex担当は割り当てのTask/Dispatchの手順で質問し、返答待ちでターンを終える。Claudeは依頼書や確定仕様から回答できる質問に自分で回答する。新しい仕様判断が必要な質問だけユーザーへ戻す。
- 成果物は画像パス、寸法・alpha・原画/指示の記録、実施した確認と未対応を含めて返す。担当側で実行できない工程を成功と報告しない。
- Claudeは返却通知を受け、担当の検証証拠を確認する。問題があれば同じDispatch宛に `orchestration send` で具体的な修正箇所と維持事項を送り、再生成が不要なものを作り直さない。無回答や時間経過だけを理由に重複起動しない。
- 受け入れ後はClaudeが画像登録・組み込み・必要なテストとPC/スマホの実表示確認を行う。画像生成完了を機能完成と報告しない。担当の停止/失敗はOrca手順どおり扱い、生成ツールがない場合はChatGPT/Codexの画像生成可能な環境が必要であることをユーザーへ報告する。

このSkillはセッションが必要時に連携を実行する手順。常駐daemon、ファイル監視hook、全チャットへの自動転送ではない。既存チャットには、このSkillと更新したCLAUDE.mdの再読を依頼して反映する。
