# CodeChronicle 制作の入口

全要素の制作ルール・用途別仕様・固有設定・履歴を整理する。実行コードと公開済みIDはこの整理で移動・改名しない。まず[共通ルール](common.md)を読み、追加したいものから下へ進む。

## 何を作るか

| ジャンル | 要素・用途 | 正式な案内 |
|---|---|---|
| 世界・場所 | 地形、建物、小物、町、地図、ダンジョン、配置、出入口 | [世界](world.md) |
| 人物・生物 | 主人公、NPC、敵種、人物の特徴、マップ画像、会話画像 | [人物](characters.md) |
| 動き・演出 | 歩行、攻撃、魔法、状態変化、カメラ、回復・レベルアップ | [動き](motion.md) |
| 物語・進行 | 世界設定、章、会話、イベント、クエスト、解放条件 | [物語](narrative.md) |
| 教材・学習 | 問題、本、解説、採点、出題、復習、学習記録 | [学習](learning.md) |
| ゲームルール | 戦闘、能力、成長、道具、装備、店、宝箱、報酬 | [ゲームルール](gameplay.md) |
| 画面・表現・操作 | UI、文字、背景、音楽、効果音、キー・タッチ、案内 | [画面・音・操作](presentation.md) |
| 状態・保存 | 進行状態、設定、セーブ、移行、復元、書き出し・読み込み | [保存](persistence.md) |
| 制作・運用 | Skill、担当、レビュー、検証、生成履歴、ビルド、公開、登壇資料 | [制作と運用](operations.md) |

各ファイルの主分類は[既存のファイル台帳](../architecture/file-inventory.json)の `genre` に記録する。主分類は一つ、関連する用途・環境・状態は複数持てる。台帳は所在の索引で、実装設定のコピーではない。更新と検査は `node scripts/production-inventory.mjs --write`、`node scripts/production-inventory.mjs --check`。

既存台帳の `lines`・`imports`・`staticReferenceHints` は元の詳細調査として保持し、その調査時点を `detailSnapshot` に記す。今回の検査は現在のファイル・サイズ・主分類・リンクを確認するもので、過去の依存解析が最新になったとは扱わない。

## 共通の用途別仕様

| やりたいこと | 再利用する仕様 | 固有情報の例 |
|---|---|---|
| 人物の会話用画像を作る | [キャラクターの会話用画像](uses/dialogue-portraits.md) | 人物の服装、兜、配色、顔を見せるか |
| ワールドに人物・敵を描く | [マップ用画像](uses/map-sprites.md) | 人物・敵種の特徴、表示に使う元絵 |
| 小物や背景に発光・揺れを付ける | [オブジェクトの動き](uses/object-motion.md) | 対象、位置、周期、強さ、停止条件 |
| 人物や生物を歩かせる | [歩行](uses/walking.md) | 対象、体型、足数、用意した方向 |
| 戦闘中に攻撃する | [攻撃・戦闘表現](uses/combat-art.md) | 攻撃者、武器、技、向き |
| 家具・建物・地形を作る | [環境素材](uses/environment-art.md) | 材質、環境タグ、用途、状態 |
| 扉の開閉や差分を作る | [状態差分](uses/state-variants.md) | 変更する部分、維持する部分、遷移条件 |
| タイトル・物語の背景を作る | [背景](uses/backgrounds.md) | 場所、時刻、物語上の意味、文字の置き場 |

問題の形式・採点仕様は [question-author](../../.agents/skills/question-author/SKILL.md) を唯一の管理元として参照する。音や会話イベントなどの追加手順は各ジャンルの案内に置く。同じ規則を用途別ファイルへ複製しない。

## 個別設定と履歴

- 人物の確定した特徴は[主人公](characters/hero.md)・[謎の騎士](characters/knight.md)のように人物ごとに記録する。新規は[人物設定のひな形](templates/character.md)を使う。
- 個別設定に数値を転記せず、切り出し・速度・進行条件・採点などの正本をリンクする。実測値は実行コード側の定義が正本。
- 制作・変更は[追加仕様のひな形](templates/change.md)、制作記録は[履歴のひな形](templates/record.md)を使う。
- 採用済みの画像生成履歴は[記録の索引](records.md)から辿る。記録された過去のプロンプトは、現在の共通仕様そのものではない。

## 複数ジャンルにまたがる追加

| 追加するもの | 一緒に確認するところ |
|---|---|
| NPC | 人物ID → 会話・用途別画像 → 配置と会話可能位置 → 物語条件 → 保存・履歴 |
| 敵 | 敵種 → マップ・遭遇・戦闘画像 → 配置個体ID → 行動範囲 → 問題・報酬 → 討伐記録 |
| 村・ダンジョン | 地形・建物・出入口 → 到達性 → NPC・敵・回復 → 物語・教材 → 古い位置の復元 |
| 問題 | 学習目標・形式 → 採点 → 出題登録 → 本・戦闘・クエストの参照 → 保存・復習 |
| 音 | 使用場面・再生経路 → ユーザー操作後の再生 → 消音・音量 → 設定保存 → 繰り返し・停止 |

### 次の5分で始めるなら

追加対象を一つ選び、該当ジャンルの「管理元」を開く。共通仕様・固有情報・登録先・確認方法を一行ずつ埋める。制作ルールがあっても共通登録機構まで実装済みとは限らないため、各案内の対応状況を確認する。
