# CodeChronicle 制作の案内

1. [制作の入口](../../../docs/production/index.md)と[共通ルール](../../../docs/production/common.md)を読み、依頼対象のジャンルと用途を特定する。対象の種類・用途・媒体・環境・状態を同じ分類階層へ混ぜない。
2. 該当ジャンルの案内から、正本、用途別仕様、固有情報、実装の登録先、検証先を辿る。複数ジャンルにまたがる追加は入口の関連表も使う。全案内を毎回読み込まず対象に必要な資料を選ぶ。
3. 画像制作は `game-art`、作問は `question-author`、コードレビューは `code-review` を使う。これらのルールを新しい文書へ複製しない。
4. 共通仕様＋固有設定から具体的な制作指示を作る。人物の会話用画像・歩行などを特定の人物名で別手順に分けない。実際のcrop・anchor・採点・進行・保存などは実行コード側の正本を確認する。
5. 「規約あり」「定義で追加可能」「専用実装あり」「未対応」を区別する。文書の共通化だけで汎用実装や対応素材が揃ったと報告しない。公開済みIDや保存形式を分類整理の都合で変更しない。
6. 制作・登録・対象に必要な検証を行い、採否と未対応を履歴へ残す。構成検討だけの依頼で実装しない。ルール整理だけなら実行コードの大規模再編・素材再生成を加えない。commit・push・公開は依頼範囲に従う。

ファイル分類の台帳は `docs/architecture/file-inventory.json` を使う。追加や規約変更後は `node scripts/production-inventory.mjs --write` と `--check` で更新・分類漏れ・参照先を確認し、第二の台帳を作らない。Skillだけの変更では構文・参照を検証し、アプリの全テストや画像生成を繰り返さない。
