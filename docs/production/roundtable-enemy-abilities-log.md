# 円卓会議ログ：敵の特殊能力（2026-11-22）

裏会議（おまけの楽屋話）の素材として残す記録。**決定ではない**。採用はユーザーの回答で決める。各参加者は互いの意見を見ずに独立に検討した。実プレイ・ユーザー調査はしていない。

議題：敵の特殊能力を10個ほど出し合い、凶悪度（弱い敵〜ボス級）に合わせて段階的に使う流れを考える。

## 参加者ごとの案

### 肯定派（既存の仕組みを伸ばす・小さく試せる順）
1. **キャッシュの残像**（弱／キャッシュガラス）：誤答すると次の1問に直前の誤答がもう一度出る。同じ誤答を二度選ばなければ誤解が直ったと確かめられる。
2. **メモリリーク・じわじわ**（弱〜中堅／メモリリーククラゲ）：誤答ごとに「リーク」が溜まり敵の攻撃+10%（最大3）。正解で1つ解放。
3. **デッドロックの睨み合い**（中堅／デッドロックインプ）：数ターンに1回、こたえる以外の見極め・アイテムなどを予告つきで1つ封じる。
4. **非推奨の呪い（Deprecated）**（強敵）：選択肢に「以前は正しかった古い書き方」が混ざる。選ぶと半分ダメージ＋なぜ非推奨かの解説。
5. **グラフィウスの悪手指南**（ボス級）：悪い見本コードを見せ、「この欠陥はどれか」に正解すると技を打ち消して大ダメージ。
- ボヤキ：「どれも"小さく試せます"って言ったけど、全部試したら小さくないのは知ってる。」

### 中立派（確認済みの事実と推測を分ける）
- 確認済み：誤答で次の問題を変える仕組み（`scrambled`→`withDecoys`）、黄金の敵の `elite`、`prefers-reduced-motion` の参照は既にある。
1. **キャッシュ残り**（弱／ガラス）：誤答した問題を並びを変えて次にもう一度出す。
2. **ページばさみ・小**（弱〜中堅）：ミミックの弱化版。誤答で次の問題が6択。
3. **メモリリーク**（中堅／クラゲ）：誤答で「にじみ」が溜まり攻撃上昇、正解で解放（GCのたとえ）、上限3。
4. **デッドロック**（強敵〜ボス／インプ）：予告つきで次の1問だけ見極めとヒントを封じる。HPが少ないときは発動しない。
- 時間制限は外した。凶悪度は「表示・情報の揺さぶり → 救済の制限 → 数値の圧力」の順に重ねる。1体1能力、発動は会話で予告。
- ボヤキ：「出す案の半分は『既存関数の引数を変えるだけ』です。地味ですが、誰かがそこを言わないといけないので。」

### 否定派（壊れる場面を先に潰す）
- 失敗条件：時間制限はアクセシビリティの地雷／問題文を壊す系は正解が一つに決まらなくなる／選択肢を増やす系はミミックと重なって12択に膨らむ／能力の状態をセーブするとセーブ形式が変わる（戦闘中は保存しないのが安全）／乱数発動はE2Eで再現できない（強制発動の仕組みが要る）／動き・色だけの表示は不可／誤答で能力が強まる悪循環は最悪。
- 許せる案：
  1. **未定義のささやき（undefined）**（弱）：誤答の次の1問、選択肢1つが「???」。確かめれば中身が見える。
  2. **キャッシュの亡霊**（中堅／ガラス）：直前とよく似た別の問題を出す（似た問題の組がないと成立しない）。
  3. **デッドロック封印**（中堅〜強敵／インプ）：誤答で見極めかヒントが2ターン使えない。正解1回で解除。
  4. **メモリリーク**（強敵／クラゲ）：誤答ごとに最大HPが少しずつ減る（戦闘中だけ、下限50%）。
  5. **本番環境の呪い**（ボス級）：誤答の被ダメージが増える代わりに、ボス戦前に誤答の解説を必ず確認できる（ロールバック）。
- 採用条件：①正解すれば解除 ②重ね掛けの上限 ③動きを減らす設定と文字での表示 ④テスト用の強制発動。
- ボヤキ：「タイマー案、絶対誰か出してるでしょ…。それ、スクリーンリーダーで一回プレイしてから持ってきて」

### ユーザー代弁者（初心者の手間・迷い・離脱）
1. **キャッシュ汚染**（弱／ガラス）：攻撃されると次の問題の選択肢の並びが変わる。「さっきの3番」が使えない。
2. **メモリリークの霧**（弱〜中／クラゲ）：1ターンだけ補足の説明文が「…」で隠れる（コードは残す）。
3. **デッドロックの呪縛**（中／インプ）：にげる・アイテムを2ターン封じる。HP3割未満では使わない。
4. **似非コードの擬態**（強）：誤答の1つが正解と1文字違い（`=` と `==` など）に差し替わる。
5. **締め切りの鐘**（ボス級）：時間制限。入れるなら設定でオフ必須。
- 前提：初心者が抜けるのは「何をされたか分からない」とき。発動時に名前と効果を1行で出す。初めて見た能力は図鑑に記録。「見極め」で打ち消せるとまほうの意味が増える。
- ボヤキ：「凶悪な能力を考えろって言われても、初心者にとっては4択そのものがもう十分凶悪なんだよなあ…」

### AIの代弁者（作る側の実現性）
- 現状、能力は `battle.enemy.id==='mimic-book'` の直書き（answer() に3か所、battleNext() に1か所）。あと10個足すなら先に共通の仕組みを入れるのが安い。
- 仕組み案：`src/enemyAbilities.ts` に `abilities: Record<敵ID, Ability>`（name・tier・誤答時の変形・ダメージ式・ステータス補正・文言）。Battle の `scrambled` を `curse` に一般化。変形は「問題→問題」の純粋関数にそろえて単体テスト。Battle はセーブされないので移行不要の見込み（要確認）。ミミックもこの仕組みに移す。
- 案：
  1. **スコープ迷子**（凶悪度1）：誤答で次の問題の選択肢を1つ「？？？」に伏せる。押すと開く。
  2. **ページばさみ・小**（凶悪度2）：`withDecoys` を2個で。
  3. **N+1の連撃**（凶悪度3）：同じ問題を続けて間違えるたびダメージ+1、+2…。正解でリセット、上限あり。
  4. **キャッシュ汚染**（凶悪度3〜4）：誤答した問題がこの戦闘中にもう一度出る。前回の答えに文字の印。
- 作業量：仕組み＋ミミック移行で約半日、能力1つ30分〜1時間＋テスト1本。画像は不要の見込み。入力式の問題には選択肢変形が効かないのでダメージ系に切り替える。
- ボヤキ：「凶悪な能力を10個？ まず answer() の三項演算子という最凶のボスを倒させてください」

### 先生（学習として成り立つか）
1. **誤った書き方の囁き**（弱）：誤答の次の問題に、よくある誤解を言った1行が出る。戦闘後に必ず「囁きは誤り、正しくは〜」を出す（セットで用意できないなら不採用）。
2. **選択肢の位置入れ替え**（弱〜中）：位置の暗記を崩す。害はほぼない。
3. **似て非なる写し身**（中〜強）：誤答1つを正解と1語違い（`v-if`/`v-show`、`$fillable`/`$guarded`、`PUT`/`PATCH`）に差し替え。一番学びになる。自動生成は正解が2つになる恐れがあるので、人が用意したペアだけを使う。
4. **時の結界**（ボス級のみ）：入れるなら設定でオフ・復習ターンだけ・秒数長め、が必須。
- 原則：負けたあとに正しい知識が残ること。問題やコードを読みにくくする能力（ぼかす・揺らす・隠す）は勧めない。技の名前は「誤りの例」と分かる言い回しに。
- ボヤキ：「敵が誤った知識を囁くたびに、私は解説を3行ずつ書き足すことになるんですよ……」
